# 采集与队列常驻一个进程组，投递放在 agent 侧

需要一个中转，让来源与 agent 互不认识。考虑过做成一个独立网关服务（本机 HTTP，多来源 POST 进来，消费者来拉），决定不做：那会多出一个需要单独运维、会「断」的东西，而它要解决的问题（及时、不丢、失败重试）在进程内队列里同样能解决。

最终形态是**两个程序**：常驻侧（采集子进程 + 队列 + SQLite，开机自启，DSH 关着也跑）与 agent 侧（一个很薄的投递 adapter，必须活在 agent 进程里，因为 `agent.followup()` 只有那里能调）。

后果：库由常驻侧独占写入，adapter 只是它的客户端；DSH 关闭不影响采集与留存。
