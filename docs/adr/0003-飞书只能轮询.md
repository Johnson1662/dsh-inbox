# 飞书只能轮询，因为它不给 user 身份事件订阅

飞书来源按「会话 × 时间窗口」逐个轮询，每个会话保存自己的时间水位，靠 message_id 去重。不使用 WebSocket 事件订阅。

原因不写在代码里，所以记在这里：`lark-cli event consume im.message.receive_v1 --as user` 被明确拒绝（`--as user is not supported, this command only supports: bot`），所有 `im.*` 事件都只支持 bot 身份，而本项目要求用本人账号。另外 `im +chat-list` 不返回最后消息时间，无法「只拉有变化的会话」。

后果：飞书的采集成本是**会话数 × 轮询频率**，没有便宜的捷径。user token 的限流阈值未核实，因此实现上必须并发拉、遇 429 自动降频并标记 `degraded`。
